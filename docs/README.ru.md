# dagcheck-plan

Проверьте зависимости CI или пакетного конвейера, найдите критический путь и
смоделируйте расписание с ограниченным числом исполнителей до запуска заданий.
Инструмент ничего не выполняет. Python 3.10+, только стандартная библиотека во
время работы, лицензия MIT.

[English](../README.md) · [简体中文](README.zh-CN.md) · [Deutsch](README.de.md)

## Быстрый старт

Из корня репозитория:

```sh
python -m pip install .
dagcheck-plan analyze examples/build.json --workers 2 --budget 8
python -m dagcheck_plan analyze examples/build.json --workers 2 --format json
python -m unittest discover -s tests -v
```

Пример выдаёт путь `fetch -> test -> package`. Длительность при неограниченной
параллельности и моделировании двух исполнителей равна 8. Все длительности
задаются в одной выбранной единице, например секундах.

## Формат входных данных

```json
{"tasks":[{"id":"fetch","duration":2},{"id":"test","duration":5,"needs":["fetch"]}]}
```

Корневой объект содержит только массив `tasks`. Задание требует `id` и `duration`;
необязательный `needs` по умолчанию равен `[]`. Неизвестные поля запрещены.
Идентификаторы уникальны, непусты, чувствительны к регистру и не содержат пробельных
символов по краям. ID ограничен 256 символами; категория Unicode C запрещена
(управляющие, форматирующие, суррогаты, частные и неназначенные символы). Зависимости — существующие ID без повторений. Длительность —
конечное неотрицательное число JSON, не логическое значение. Пустой граф и нулевые
длительности допустимы. Повторяющиеся ключи JSON, неизвестные или повторные
зависимости, ссылки на себя и циклы вызывают ошибку. Сообщение о цикле содержит
реальный направленный цикл, а не просто заблокированные вершины. Файлы — UTF-8;
`-` означает стандартный ввод.

## Результаты и бюджет

- `topological_order`: на каждом шаге выбирается наименьший доступный ID.
- `critical_path`: один связный максимальный путь от источника до стока;
  при равенстве выбирается лексикографически наименьшая последовательность ID.
- `timings`: ранние и поздние начала/окончания и резерв времени при неограниченной
  мощности. Для несвязанных компонент используется общее окончание проекта.
- `unlimited_worker_makespan`: длина критического пути, нижняя граница длительности.
- `worker_lower_bound`: максимум этой длины и общего объёма работы / числа исполнителей.
- `schedule`: невытесняющее расписание на одинаковых исполнителях. Приоритет —
  наибольшая оставшаяся длина критического пути, затем ID. Все завершения в текущий
  момент обрабатываются перед назначением новых заданий. Нулевая задача завершается
  сразу, и её потомки участвуют в следующем назначении. Выбирается свободный
  исполнитель с наименьшим номером.
- `heuristic_makespan`: длительность конкретного допустимого расписания.
  Глобальная оптимальность не гарантируется; превышение бюджета не доказывает,
  что уложиться в него невозможно.

`--workers` по умолчанию **1**. `--budget` всегда ограничивает смоделированную
длительность, а не нижнюю границу. Равенство допустимо. Без бюджета `within_budget`
равно JSON null. Коды выхода: **0** — корректно и бюджет соблюдён или не задан;
**1** — корректно, но расписание превышает бюджет; **2** — ошибка входных данных,
параметров или чтения файла. Отчёт идёт в stdout, диагностика — в stderr.

Внутри используются точные рациональные числа десятичного представления уже
разобранных значений: 0.1 + 0.2 укладывается в бюджет 0.3. Дробный JSON сначала
разбирается как Python float, поэтому произвольная десятичная точность не сохраняется.
Ненулевые числа JSON и бюджеты CLI, которые при разборе обращаются в ноль из-за
потери порядка (например, `1e-400` или `-1e-400`), отклоняются как недопустимый ввод.
Точный ноль и представимые субнормальные значения по-прежнему принимаются.
Дробный вывод округляется до конечного float, целый вывод точен; бюджет проверяется
до округления вывода.

## Библиотека

```python
from dagcheck_plan import loads, plan, PlanError
report = plan(loads('{"tasks":[{"id":"lint","duration":3}]}'), workers=2, budget=4)
assert report["within_budget"] is True
```

`plan` принимает словарь и не изменяет его. `loads` строго разбирает JSON. Ошибки
вызывают `PlanError`, подкласс `ValueError`. Перестановка заданий и зависимостей
не меняет результат.

## Ограничения и разработка

Это планирование по оценкам, не гарантия времени выполнения. Нет запуска команд,
чтения секретов CI, моделирования запуска исполнителей, кеша, повторов или классов
ресурсов. Это не оптимизатор и не защитная песочница. Ограничения: 1 000 000 символов ввода, 10 000 заданий, 100 000 рёбер.
Лимиты заданий и рёбер действуют и для API со словарём;
рациональная арифметика больших графов может быть дорогой. Используйте доверенные
конфигурации проекта. NetworkX предоставляет общие алгоритмы графов, PyGraphviz —
интеграцию с Graphviz; здесь цель — компактная CLI-проверка бюджета без выполнения.

Тесты покрывают схему, циклы, длинные цепи, нулевое время, перестановки, одновременные
завершения, бюджет, CLI и 100 случайных DAG с фиксированным seed. CI проверяет
Python 3.10–3.13 и установленную команду. Сравнение графов, классы ресурсов и адаптер
GitHub Actions пока лишь планы. Для вклада добавляйте регрессионные тесты и обновляйте
все четыре перевода: [руководство](../CONTRIBUTING.md). Лицензия [MIT](../LICENSE).
